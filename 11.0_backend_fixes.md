## 1. Application Status Updates - Role Permissions

### Issue
**Endpoint:** `PUT /api/applications/{id}/status`

**Problem:** Only RECRUITER role can update application status. JOB_SEEKER role is blocked.

**Error:**
```json
{
  "status": 400,
  "error": "Bad Request",
  "message": "User role does not allow this action",
  "path": "/api/applications/{id}/status"
}
```

**Impact:** Job seekers cannot mark jobs as complete, blocking the mutual completion flow.

### Fix Required
Allow JOB_SEEKER role to update application status to `COMPLETED`.

```java
// In ApplicationService.updateApplicationStatus()
if (newStatus == ApplicationStatus.COMPLETED) {
    // Allow both RECRUITER and JOB_SEEKER to mark as complete
    if (!userRole.equals("RECRUITER") && !userRole.equals("JOB_SEEKER")) {
        throw new ForbiddenException("User role does not allow this action");
    }
} else {
    // Only RECRUITER can change to other statuses
    if (!userRole.equals("RECRUITER")) {
        throw new ForbiddenException("User role does not allow this action");
    }
}
```

**Priority:** 🔴 HIGH

## 3. Review Creation - Completion Requirement

### Issue
**Endpoint:** `POST /api/reviews`

**Problem:** Reviews can only be created for COMPLETED applications.

**Error:**
```json
{
  "status": 422,
  "error": "Unprocessable Entity",
  "message": "Application not completed",
  "path": "/api/reviews"
}
```

**Impact:** Reviews can only be submitted after jobs are marked as COMPLETED.

### Status
✅ This is **CORRECT BEHAVIOR** - not a bug. Reviews should only be allowed for completed work.

**Note:** This works correctly once Fix #1 is implemented (allowing job seekers to mark as complete).

**Priority:** N/A (Depends on Fix #1)

## 4. Application Status Transitions

### Current Flow (Backend Enforced)
```
PENDING → ACCEPTED → COMPLETED
```

### Documented Flow (API Spec)
```
PENDING → VIEWED → REJECTED/ACCEPTED → IN_PROGRESS → PENDING_COMPLETION → COMPLETED/CANCELLED
```

### Issue
Intermediate statuses (IN_PROGRESS, PENDING_COMPLETION) may not be properly implemented or validated.

### Fix Required
Verify and implement all application status transitions as documented in `fixed_api_spec.json`.

**Priority:** 🟡 MEDIUM
